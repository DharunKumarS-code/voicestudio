# PDF Voice Reader

Open a PDF in your web browser and hear it read aloud, live, starting from any page or sentence.
Narration begins within a few seconds and continues page after page until you stop it. Nothing is
uploaded anywhere: the PDF stays in your browser, and the speech is generated by the VoiceStudio
backend on your own computer.

It is a separate feature from the Audiobook workspace (`/audiobook`), which remains in the desktop
app's navigation (sidebar, Home and command search) alongside it, for producing finished M4B/MP3
files with a full multi-voice cast — see [Electron Stories and Audiobooks](electron-longform.md).

## Opening the reader

**Desktop app.** Choose **PDF Voice Reader** in the sidebar (Stories group), on Home, or in the
command search (Ctrl+K). The app:

1. reuses the local backend if it is already running, or starts it (once — repeated clicks share
   one launch, and never start a second backend);
2. waits until the backend reports ready and checks that it serves the reader page;
3. opens the reader in your **default browser**, on the port the backend actually uses
   (normally `http://127.0.0.1:3900/reader/`).

If something prevents this, the app says why in a notification (setup not finished, the port is
taken by another program, the backend failed to start, the browser could not be opened — with the
address to open by hand). It never opens a page that would not work.

**Directly.** While VoiceStudio is running, open `http://127.0.0.1:3900/reader/` (or your
`OMNIVOICE_PORT`) in any modern browser.

**Web build / Docker.** The reader is served next to the API the web UI already uses
(`<your VoiceStudio address>/reader/`); the entry in the web UI opens it in a new tab.

## Reading

- **Open PDF** (or drag a PDF onto the page). Text is extracted one page at a time with PDF.js, only
  when needed, so a 200-page book is ready instantly.
- Pick a page and press **Read this page**, or **click any sentence** to start there.
- **Pause / Resume**, **Stop**, **Voice** and **Speed** — changing voice or speed restarts from the
  sentence you are hearing so the change applies at once.
- The current sentence is highlighted and the view follows the narration across pages.
- Pages without a text layer (scanned images) are named as such and skipped.
- Keyboard: Space play/pause, ← → pages, Esc stop. The reader remembers your last page per PDF and
  your voice.

## How it works

Each few sentences of the current page go to the backend's streaming endpoint `/ws/tts`, which
synthesizes sentence by sentence with the active engine (OmniVoice by default) and streams PCM audio
back; the browser plays it gaplessly with the Web Audio API. The reader keeps about 25 seconds of
audio ahead of what you hear and requests no further than that, so Stop wastes little GPU time and
long books never pre-generate. The page and its assets are static files in `backend/reader/`
(PDF.js 3.11.174 is vendored under `backend/reader/vendor/pdfjs/`, Apache-2.0), served by the backend
at `/reader/`; every URL in the page is relative, so it also works behind a path prefix.

## Requirements

- The VoiceStudio backend running locally with a TTS engine installed (the default OmniVoice model).
  The first narration after a backend start loads the model, which can take up to a minute.
- For real-time narration, generation must be faster than playback. A CUDA GPU or Apple Silicon is
  comfortably faster (an RTX 3050 6 GB measured 2–4× real time with OmniVoice); a slow CPU may
  pause between passages ("Buffering…").
- A current Chrome, Edge, Firefox or Safari.

## Deployment notes

- Installers include the reader: `backend/` is packaged as a resource and copied whole into the
  runtime project, so `/reader/` is served by every packaged backend.
- Narration shares the GPU queue with every other job (one generation at a time on cards with less
  than 10 GB), so running an audiobook export at the same time slows both rather than overloading
  the GPU.

## Known limitations

- **Remote backends are not supported.** With the desktop app connected to a remote backend, the
  launcher explains this instead of opening the browser: an ordinary browser tab cannot present the
  backend's API key, and putting the key in the page would expose it. Use the reader on the
  computer that runs the backend.
- **No OCR.** Scanned pages without a text layer are skipped.
- **Narration is not saved.** Use the Audiobook workspace to produce a file.
- Streaming is per sentence: the first sound arrives after the first sentence is generated.
- Technical details in launcher errors (the backend's own words) are shown untranslated.
